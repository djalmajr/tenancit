# Relatório de escala e gate de paginação — 2026-07-11

## Decisão

**`KEEP_FULL_LISTS` nas quatro superfícies nesta entrega.** Não há
cardinalidade operacional de produção declarada; portanto o volume observado do
gate permanece `0`. A curva sintética mede capacidade, mas não autoriza mudar o
contrato HTTP por especulação.

O primeiro hard trigger repetível agora aparece em **500 definições** (UI p95
acima de 150 ms). Esse é o próximo checkpoint de coleta/reavaliação. Em 1.000,
overview, definições e API clients repetem o limite de UI e o payload supera
250 KiB; em 5.000, os payloads superam 500 KiB e API clients também excede 300
ms de HTTP p95.

## Protocolo executado

- comando: `TENANCIT_SCALE_OBSERVED_VOLUME=0 make benchmark-scale`;
- commit: `301b470470468e3be649f9bf33da97313e6376ef`, worktree limpo;
- datasets: 100, 500, 1.000 e 5.000 registros, com clients contendo preview,
  RPM, expiração e os dois scopes obrigatórios;
- duas rodadas por cardinalidade;
- HTTP: 10 warm-ups + 100 amostras, concorrências 1 e 10;
- browser: 5 warm-ups + 30 amostras, viewport 1440×900;
- superfícies: tenants, definitions, API clients e overview;
- ambiente: Apple M2 Max (12 CPUs), macOS arm64 25.5.0, PostgreSQL 16.14,
  Chrome 150.0.7871.115;
- stack isolada removida ao final, sem container residual.

Os JSONs, amostras e planos SQL permanecem localmente em
`benchmarks/scale/results/20260711t210603z-68694/`, ignorados pelo Git.
