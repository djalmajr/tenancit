=== Arquitetura

O Tenancit é uma imagem Go com três comandos: API HTTP + painel SPA embutido,
migration one-shot e rewrap AES offline. O desenho favorece poucas
partes móveis: não há broker, ORM mágico ou serviço separado para o painel.
PostgreSQL mantém domínio/sessões/auditoria e Valkey sustenta o rate limit global.

==== Visão de 30 segundos

* `server/` contém o binário Go, handlers HTTP, services, migrations e código
  sqlc gerado.
* `web/` contém a SPA admin em React + TanStack Router + Tailwind/shadcn.
* `web/dist` é copiado para `server/internal/spa/dist` e servido pelo Go via
  `embed.FS`.
* `/v1/admin/*` usa sessão OIDC opaca server-side, RBAC e CSRF. O token
  administrativo só existe como break-glass explícito ou modo local legado.
* `/v1/identify` e `/v1/resolve*` são protegidos por API clients
  (`Authorization: Bearer`).
* Segredos ficam cifrados no banco e só são descriptografados server-side.

==== Fluxo de consumo

[source,mermaid]
----
sequenceDiagram
  participant E as Edge / injector
  participant A as Aplicação consumidora
  participant T as Tenancit
  participant PG as PostgreSQL

  E->>T: GET /v1/identify?hostname=tenant.example.com
  Note over E,T: Bearer API client + If-None-Match opcional
  T->>PG: hostname -> tenant ativo
  T-->>E: tenantSlug + ETag (ou 304)
  E->>A: x-tenant-id: tenantSlug
  A->>T: GET /v1/resolve?tenantId=tenant-slug
  Note over A,T: Bearer API client + If-None-Match opcional
  T->>PG: tenant + recursos ativos + fields + values
  T->>T: decrypt de secrets
  T-->>A: tenantSlug + resources + ETag (ou 304)
----

Nesse contrato, `tenantId` recebe o slug canônico devolvido como `tenantSlug`.
O `ETag` de identify representa a identidade do tenant; o de resolve representa
a configuração vigente. Cada chamador revalida o próprio estado e, diante de
`304 Not Modified`, mantém o valor já carregado sem novo payload. Os dois
validadores não são intercambiáveis.

Para integrações em que edge e aplicação são o mesmo componente, permanece
suportado `GET /v1/resolve?hostname=tenant.example.com`. Esse caminho alternativo
faz identificação e resolução completa em uma chamada e, portanto, entrega os
secrets ao chamador autenticado. A fonte normativa de payloads, cache e erros é
<<eng-contratos-http,Contratos HTTP>>.

==== Camadas

[cols="1,3",options="header"]
|===
| Camada | Papel

| `httpapi`
| Parse HTTP, status code, JSON e roteamento chi. Não deve concentrar
  invariantes de domínio quando houver serviço canônico.

| `service`
| Regras de negócio: provisionamento transacional, encode/decode, montagem de
  resources e resolver de consumo. Listagens de resources carregam headers e
  fields/values em duas queries batch constantes, sem queries por resource.

| `store`
| SQL explícito e código sqlc gerado. Migrations ficam em pacote separado que o
  runtime HTTP é proibido de importar.

| `web`
| Painel admin. Não é fonte de verdade de segurança; secrets e validações
  críticas ficam no servidor.
|===
