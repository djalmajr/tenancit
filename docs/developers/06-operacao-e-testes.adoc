=== Operação e testes

==== Variáveis obrigatórias

[cols="1,3",options="header"]
|===
| Variável | Descrição

| `TENANCIT_ADDR`
| Endereço do HTTP server. Default: `:8080`.

| `TENANCIT_DATABASE_URL`
| DSN PostgreSQL. Obrigatória.

| `TENANCIT_ADMIN_AUTH_MODE`
| `oidc` ou `legacy_shared_token`; obrigatório e validado no boot.

| `TENANCIT_ADMIN_ORIGIN`, `TENANCIT_OIDC_*`
| Origin, issuer, client confidencial, role claim e mappings; obrigatórios em OIDC.

| `TENANCIT_ADMIN_TOKEN`
| Obrigatório no modo legado dev. Em OIDC, só é aceito com
  `TENANCIT_BREAK_GLASS_ENABLED=true`, versão declarada e ao menos 32 caracteres.

| `TENANCIT_AES_KEY`
| Chave AES-256-GCM atual em base64. Obrigatória.

| `TENANCIT_AES_KEY_VERSION`
| Versão da chave atual. Opcional; use explicitamente em produção.

| `TENANCIT_AES_KEY_V<n>`
| Chave adicional do keyring para decriptar versões históricas ou staged em
  cutover. Não muda a versão usada para novos writes.

| `TENANCIT_OPERATIONS_REPORT_TOKEN`, `TENANCIT_OPERATIONS_REPORT_CREDENTIAL_VERSION`
| Credencial exclusiva e versionada para agentes publicarem reports de
  backup/restore/migration/rewrap. O par é opcional; quando configurado, o token
  deve ter pelo menos 32 caracteres.

| `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SERVICE_NAME`
| Habilitam exportação OTLP/HTTP. Sem endpoint, telemetria externa fica
  desligada. HTTP sem TLS exige `OTEL_EXPORTER_OTLP_INSECURE=true` explícito.
|===

==== Gates locais

[source,bash]
----
make test
make test-go
make test-go-strict
make test-web
make e2e-oidc
----

`make test-go` roda `go vet ./...` e `go test ./...`. Os testes HTTP/store usam
testcontainers e pulam se Docker não estiver disponível. `make test-go-strict`
(também disponível como `make test-db`) define `REQUIRE_DB_TESTS=1`: se o Docker
não puder iniciar o PostgreSQL efêmero, o gate falha em vez de pular a cobertura.

`make test-web` roda ESLint (incluindo as regras de hooks), o typecheck TypeScript
e a suíte Vitest. `make test` é o gate local padrão e combina Go, lint, typecheck
e testes web. Na CI, use o modo estrito para que indisponibilidade do Docker seja
visível como falha.
`make e2e-oidc` sobe PostgreSQL, Valkey e Dex descartáveis e prova login OIDC,
sessão opaca, CSRF, logout/revogação e break-glass least-privilege sem retries.

==== Healthcheck

[source,http]
----
GET /healthz
----

Resposta esperada:

[source,json]
----
{"status":"ok"}
----

Readiness síncrona e sanitizada:

[source,http]
----
GET /readyz
----

Retorna `503` quando uma dependência crítica está indisponível e nunca inclui
DSN, URL, erro interno ou credencial. O contrato de dimensões, redaction, SLOs e
reports está em link:observability.md[Observabilidade e política de redaction].

==== Operação segura

* Guarde client secret OIDC, eventual token break-glass, `TENANCIT_AES_KEY` e
  API client tokens em secret manager.
* Rotacione API clients revogando o antigo e criando um novo.
* Não reutilize a chave AES de demo do compose.
* Exponha `/v1/resolve` apenas por TLS.
* Trate `?reveal=true` como operação sensível.
* Valide health, fronteiras de autenticação, ETag e cleanup com
  `make smoke` após deploys.
* Use os procedimentos versionados em link:runbooks/README.md[`docs/runbooks/`]
  para bootstrap, backup/restore e resposta pós-deploy.
