=== Arquitetura

O Tenancit é um binário Go que combina API HTTP, painel SPA
embutido, migrations e acesso direto ao PostgreSQL. O desenho favorece poucas
partes móveis: não há broker, cache externo, ORM mágico ou serviço separado
para o painel.

==== Visão de 30 segundos

* `server/` contém o binário Go, handlers HTTP, services, migrations e código
  sqlc gerado.
* `web/` contém a SPA admin em React + TanStack Router + Tailwind/shadcn.
* `web/dist` é copiado para `server/internal/spa/dist` e servido pelo Go via
  `embed.FS`.
* `/v1/admin/*` é protegido por `TENANCIT_ADMIN_TOKEN`.
* `/v1/resolve*` é protegido por API clients (`Authorization: Bearer`).
* Segredos ficam cifrados no banco e só são descriptografados server-side.

[source]
----
tenancit/
├── server/
│   ├── cmd/server/              # boot, env, migrate, HTTP server
│   ├── internal/httpapi/         # chi routes e handlers
│   ├── internal/service/         # regras de domínio, cripto, resolver
│   ├── internal/store/           # migrations, sqlc queries, db gerado
│   └── internal/spa/             # embed do build web
├── web/
│   └── src/                      # painel admin
├── docs/                         # esta documentação
└── planning/tenancit/
----

==== Camadas

[cols="1,3",options="header"]
|===
| Camada | Papel

| `httpapi`
| Parse HTTP, status code, JSON e roteamento chi. Não deve concentrar
  invariantes de domínio quando houver serviço canônico.

| `service`
| Regras de negócio: provisionamento transacional, encode/decode, montagem de
  resources e resolver de consumo.

| `store`
| SQL explícito, migrations goose e código sqlc gerado.

| `web`
| Painel admin. Não é fonte de verdade de segurança; secrets e validações
  críticas ficam no servidor.
|===
